# Ранковий «Мікс» · 4.0.27

Каталог отримує нову добірку з вибраних у налаштуваннях категорій після **07:00 за місцевим часом телефона**, навіть якщо застосунок не відкривали. Після встановлення цієї версії слід один раз відкрити StellarShift: він передасть вибрані категорії та поточний ключ native-планувальнику.

## Поведінка й обмеження

- WorkManager перевіряє можливість оновлення з мінімальним інтервалом 15 хвилин. Перша перевірка планується на наступні 07:00. Фактичний запуск залежить від мережі, Doze та обмежень Samsung; точне виконання о 07:00 не гарантується. Нових дозволів чи точних будильників немає.
- Одна успішна фонова добірка на місцевий календарний день. Успішний ручний шафл після 07:00 також вважається свіжою добіркою дня. Ручні оновлення залишаються доступними.
- До 12 послідовних пошукових запитів на спробу, до 10 фото з кожного запиту. При першій помилці спроба зупиняється; попередня добірка зберігається повністю. Повтор не раніше ніж за годину. Через повтори та ручний шафл денна кількість запитів може перевищувати 12.
- Зберігаються метадані й посилання на фото, а не всі файли зображень. Зображення підвантажує наявний механізм відображення; повної офлайн-бібліотеки ця зміна не створює.
- Нова добірка з'являється при відкритті вкладки «Каталог» або поверненні застосунку з фону. Постійно відкритий екран сам не переставляє плитки під пальцем.
- Зміна категорій/ключа синхронізується з планувальником. Пізня фонова відповідь не перезаписує новіший ручний шафл або інший рецепт категорій. Старий кеш іншого рецепта не показується як новий вибір.
- Після перезавантаження розклад відновлюється; зміна часу/часового поясу переплановує його. Перехід літнього часу враховано календарним розрахунком. Примусова зупинка застосунку Android блокує фонові завдання до наступного відкриття.
- З 4.0.27, якщо автозміна ввімкнена, єдине джерело — «Мікс» і немає активних колекцій, каталог та шпалери використовують одну добірку. Ранковий worker після успішної публікації одразу завантажує й встановлює перше неприховане фото. Наступні зміни беруть фото з цього пулу; окремий 24-годинний пошуковий перезбір для такого режиму не виконується.
- Ручний шафл каталогу також ставить фонове завдання підхоплення нового пулу. Воно не обходить нічну паузу і не вмикає вимкнену автозміну. Самі кнопки «Змінити зараз» зберігають наявну поведінку явної ручної дії.
- Під час нічної паузи нова добірка зберігається, а фото застосовується при наступному дозволеному запуску ранкового worker або автозміни після паузи. Не гарантовано рівно в хвилину завершення паузи. Помилка завантаження фото не змінює поточну шпалеру; незавершений перехід буде повторено. Позначка застосованої добірки переживає перезапуск.
- Дедуп, фільтр людей із fallback і ліміт двох фото на автора відповідають каталогу; заблоковані фото додатково відсіює native-сховище. Якщо вся нова добірка прихована, старий пул зберігається.
- Інтервал і вибраний екран не змінюються; планові зміни продовжують існуючий розклад. Активні колекції та поєднання кількох категорій працюють окремо. Функція не обходить ліміти Unsplash.

## Перевірено на сервері

```bash
node --test scripts/morning-mix.test.cjs scripts/catalog-cache.test.cjs scripts/catalog-loading.test.cjs scripts/rotation.test.cjs
bash scripts/test-morning-mix-native.sh
bash scripts/test-blocked-native.sh
npx tsc --noEmit
npm run lint
```

Для 4.0.27 пройшли 41 JS-тест, 18 Kotlin-тестів Міксу та 4 перевірки приховування: правильна доба/07:00, літній час (23/25 годин), часовий пояс, збереження старої добірки, cooldown, гонки ручного й фонового оновлення, зміна категорій/ключа, використання native-кешу без API-запитів. Kotlin-сховище перевірене зі SharedPreferences у пам'яті, JS — з підміною API. Android `:app:compileReleaseKotlin` пройшов; APK не створювався.

## Перевірка на S23 Ultra після окремої збірки

1. Відкрити застосунок після оновлення, вибрати категорії «Міксу» й запам'ятати перші фото. Залишити застосунок у фоні на ніч без примусової зупинки.
2. Після 07:00 при доступній мережі дати Android час виконати завдання, відкрити «Мікс»: добірка має оновитися. Повторні відкриття мають зберігати її порядок.
3. Наступного ранку без інтернету перевірити збереження попередньої добірки. Після повернення мережі й виконання фонового завдання — появу нової.
4. Зробити ручне оновлення після 07:00: фонове завдання цього дня не повинно повторно міняти добірку.
5. Змінити категорії, повернутися в «Мікс»: старий вибір не підміняє новий. Перезапустити застосунок — налаштування й успішна добірка зберігаються.
6. Окремо перевірити перезавантаження телефона та наступний ранковий запуск. Це ще не перевірено на сервері й не випливає з успішної компіляції.

## Додатковий QA 4.0.27

1. Після встановлення відкрити застосунок для синхронізації налаштувань. Увімкнути автозміну, обрати лише «Мікс», вимкнути активні колекції. Поза нічною паузою оновити «Мікс»: без ручного встановлення має з'явитися його перше доступне фото, потім автозміна продовжує цю добірку.
2. Повторити після ранкового фонового оновлення без відкриття застосунку. Перевірити live/static і вибраний екран.
3. Вимкнути автозміну або обрати колекцію: оновлення «Міксу» не змінює шпалеру. Під час завантаження переключити джерело/OFF: старий результат не встановлюється.
4. Задати нічну паузу, що включає час оновлення: фото не змінюється в паузі, але новий пул підхоплюється після неї. При помилці API лишається старий пул; при недоступності самого фото — поточна шпалера до повтору.
5. Приховати перше фото добірки: наступне доступне може встановитися, приховане — ні. Повторна фонова перевірка не повертає вже встановлене перше фото. Після перезапуску це зберігається.
